# HeldOutV1 — frozen held-out code for evaluation

`HeldOutV1.jsonl` is the fixed "code the model has never seen" set used by `bun run eval --HeldOut=Data/Eval/HeldOutV1.jsonl`
and by the **Evaluate models** workflow. One whole source file per line: `{"Kind": "ts|js|go|css|html", "Id": "owner/repo:path", "Content": "..."}`.
BPB is reported per kind (`bpb.ts`, `bpb.go`, …) plus `bpb.all`.

**Why these repositories:** none of them appears in any data spec (`Data/Spec*.json`), so no model trained by this project has
seen them — unlike the validation side of the training corpus, whose split depends on file contents that can change between
collections. Files were selected with the training pipeline's own rules (`IsSubstantiveCodePath`, `PrepareRepoFile` with a
200 B – 50 KB window, per-file license-header check) and every repository's LICENSE was verified permissive by `DetectSpdx`
(two candidates, `unjs/pathe` and `unjs/cookie-es`, were excluded because their license text goes beyond the template).
Caps: 60 files / 160 KB per kind. Thin kinds: css (12 files), html (1 file); no sql.

**Frozen:** do not edit this file. A changed set needs a new version (`HeldOutV2.jsonl`), or the numbers stop being comparable.
